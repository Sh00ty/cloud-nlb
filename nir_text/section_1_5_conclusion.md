### 1.5 Выводы

Проведённый обзор существующих систем L3/L4 балансировки нагрузки демонстрирует отсутствие полноценных открытых решений, которые могли бы быть непосредственно использованы облачным провайдером. Каждый из рассмотренных проектов решает определённое подмножество задач, однако ни один не покрывает всех формулируемых требований.

Google Maglev задаёт эталонную архитектуру программного балансировщика, а именно ферму равноправных узлов с ECMP, kernel bypass для высокой производительности, консистентное хеширование для связности соединений и DSR. Однако система является проприетарной, привязанной к внутренней инфраструктуре Google и недоступной для воспроизведения вне компании.

Cloudflare Unimog демонстрирует альтернативный подход с динамическим перебалансированием, актуальный для граничных сетей с непредсказуемой нагрузкой. Для контролируемой среды централизованного дата-центра, характерной для облачного провайдера, архитектура Maglev оказывается более подходящей.

Yandex Cloud подтверждает ключевые архитектурные решения Maglev и демонстрирует практическую реализацию декомпозиции системы на независимые компоненты. Публикация показывает, как организовать проверки состояния и управляющую плоскость в соответствии с требованиями отказоустойчивости и масштабируемости.

Исследование решений для плоскости данных выявило три технологических направления. IPVS представляет собой зрелое, но ограниченное по производительности решение. Katran показывает промежуточные характеристики на основе XDP/eBPF. VPP обеспечивает максимальную производительность благодаря полному обходу ядра и векторной обработке. Дальнейшее обоснование выбора технологии для плоскости данных приведено в разделе 3.

Поэтому для реализации полноценного облачного L3/L4 балансировщика нагрузки необходимо собирать решение из компонентов, проектировать собственную управляющую плоскость и систему проверок состояния. Обзоры существующих подходов к этим компонентам приведены в начале соответствующих разделов настоящей работы.
