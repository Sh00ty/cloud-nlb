# Сборка НИР_БАЛАНСЕР_ОТЧЕТ.docx

Скрипт `build_nir_docx.py` собирает итоговый docx из набора `*.md` файлов, сохраняя в неприкосновенности первые страницы оригинала (титул + задание на ВКР).

## Быстрый старт

```bash
cd nir_text
python3 build_nir_docx.py
```

Открыть результат в Word и нажать **F9** на содержании, чтобы оно подтянуло заголовки. Готовый файл — `nir_text/НИР_БАЛАНСЕР_ОТЧЕТ.docx`.

## Зависимости

```bash
pip3 install python-docx
```

Стандартная библиотека Python 3.9+; никаких других внешних инструментов (pandoc, LibreOffice) не требуется.

## Что делает скрипт

1. Восстанавливает `НИР_БАЛАНСЕР_ОТЧЕТ.docx` из бэкапа `НИР_БАЛАНСЕР_ОТЧЕТ.backup.docx`. Это нужно для идемпотентности: иначе при повторном запуске скрипт начнёт обрезать ранее сгенерированный контент. **Если меняешь титульный лист или задание на ВКР — обнови бэкап**: `cp НИР_БАЛАНСЕР_ОТЧЕТ.docx НИР_БАЛАНСЕР_ОТЧЕТ.backup.docx`.
2. Удаляет всё содержимое после параграфа `KEEP_LAST = 97` (последний — «Срок выполнения работы»). Первые страницы (титул + задание) остаются как есть.
3. Переписывает стили `Heading 1..5` и нормализует их под академическое оформление (TNR 14 pt, левое выравнивание, отступ 1.25 см и так далее).
4. Добавляет в футер поле `PAGE` (номер страницы по центру).
5. Вставляет TOC-поле для автособираемого содержания.
6. Идёт по списку файлов из `FILES` (порядок зафиксирован в скрипте) и для каждого парсит markdown и добавляет элементы в документ.

## Конвенции markdown

### Заголовки

Скрипт мапит уровни так:

| markdown | стиль Word | визуально |
|---|---|---|
| `##` (числовой, начинается с цифры) | Heading 1 | слева, отступ 1.25 см, разрыв страницы перед |
| `##` (нечисловой: РЕФЕРАТ, ВВЕДЕНИЕ и т.п.) | Heading 5 | по центру, без отступа, разрыв страницы перед |
| `###` | Heading 2 | слева, отступ 1.25 см |
| `####` | Heading 3 | слева, отступ 1.25 см, курсив |
| `#####` | Heading 4 | слева, отступ 1.25 см, курсив |

Heading 5 имеет `outlineLvl=0`, поэтому в TOC попадает на верхний уровень (рядом с числовыми главами).

Файл `intro.md` — особый случай: первая строка `ВВЕДЕНИЕ` без `##` распознаётся как Heading 1, который автоматически переходит в Heading 5 по правилу «начинается не с цифры».

### Списки

Любая строка вида `- текст` или `* текст` превращается в абзац, начинающийся с длинного тире (`— `). Тире-маркер не использует Word-нумерацию — это просто абзац с символом тире в начале, отступ первой строки 1.25 см.

### Жирный

`**текст**` превращается в run с `bold=True`. Курсив (`*текст*`) не поддерживается на уровне inline.

### Таблицы

Markdown-таблицы вида
```
| Колонка1 | Колонка2 |
|---|---|
| значение | значение |
```
автоматически конвертируются в Word-таблицу с границами. Шапка жирная, центрируется по вертикали в ячейке.

### Рисунки

Два формата плейсхолдеров:

1. **Скобочный:** `[Рисунок N — Подпись рисунка]` — превращается в плейсхолдер `[место для рисунка]` (курсив, по центру) + подпись «Рисунок N — Подпись» по центру под ним.
2. **Скриншот-стиль:** `Снимок экрана 2026-MM-DD в HH.MM.SS.png — Подпись` — обрабатывается аналогично.

**Нумерация рисунков сквозная по документу** — счётчик `FIG_COUNTER` инкрементируется при каждом плейсхолдере. Поэтому, если меняешь порядок рисунков, **руками поправь номера в ссылках «На рисунке N»** в теле параграфа — скрипт их не пересчитывает.

### Запрещённые символы

`clean_academic()` автоматически удаляет:
- бэктики `` ` `` (внутренний текст сохраняется без обрамления);
- стрелки `→` и `->` (заменяются на длинное тире `—`).

Если нужны новые запрещённые символы в академическом стиле — дописать в функцию `clean_academic()`.

### Особый случай: `definitions.md`

Все строки `**Термин** — Определение` собираются в безбордюрную двухколоночную таблицу (термин слева 30%, определение справа 70%). Заголовок секции (`## ОПРЕДЕЛЕНИЯ…`) и вводный абзац добавляются перед таблицей. Логика — в `process_md_file()` / `render_definitions_table()`.

## Порядок файлов

Менять в константе `FILES` в `build_nir_docx.py`. Текущая последовательность:

```
abstract.md → intro.md → definitions.md →
section_1_1_maglev.md ... section_1_5_conclusion.md →
section_2_architecture.md → section_3_dataplane.md →
section_4_agent.md → section_5_cpl.md → section_6_hc.md →
section_8_testing.md → conclusion.md → references.md
```

Имя `section_8_testing.md` исторически осталось с цифрой 8, но заголовки внутри файла уже пронумерованы 7.x.

## Часто встречающиеся правки

| Задача | Где править |
|---|---|
| Изменить порядок глав | `FILES` в `build_nir_docx.py` |
| Изменить визуал заголовков | `HEADING_STYLE_SPECS` |
| Добавить главу | положить новый `.md` в `nir_text/`, добавить в `FILES` |
| Запретить ещё один символ | `clean_academic()` |
| Изменить колонтитул / номера страниц | `add_page_numbers()` |
| Поменять формат TOC | `add_toc()` (строка с `instrText.text`) |
| Изменить диапазон сохраняемых первых страниц | `KEEP_LAST` (по умолчанию 97) |

## Проверки после сборки

Минимальный smoke-тест:

```python
from docx import Document
doc = Document("НИР_БАЛАНСЕР_ОТЧЕТ.docx")
# Заголовки
for p in doc.paragraphs:
    if p.style.name.startswith("Heading"):
        print(p.style.name, p.text[:60])
# Проверка отсутствия запретных символов
for p in doc.paragraphs:
    assert "`" not in p.text, p.text
    assert "→" not in p.text, p.text
```

## Что скрипт не делает

- Не вставляет реальные рисунки (только плейсхолдеры). PNG-файлы `whole_arch.png`, `cpl_arch.png`, `hc_cluster.png` + скриншоты Grafana вставляются в Word вручную.
- Не обновляет TOC-поле (его перестраивает Word при F9).
- Не нумерует автоматически Word-нумерацией списки и рисунки (нумерация в подписях зашита текстом).
- Не правит сквозные ссылки на рисунки «На рисунке N» — если меняешь нумерацию, синхронизируй вручную в `.md`.

## Бэкап

`НИР_БАЛАНСЕР_ОТЧЕТ.backup.docx` — это эталонный исходник с титулом и заданием на ВКР, **без** содержания работы. Скрипт восстанавливает основной файл из бэкапа при каждом запуске. Не редактируй бэкап без необходимости — он нужен как точка отсчёта для пересборки.
