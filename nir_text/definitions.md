## ОПРЕДЕЛЕНИЯ, ОБОЗНАЧЕНИЯ И СОКРАЩЕНИЯ

В настоящей работе применяют следующие термины с соответствующими определениями, обозначениями и сокращениями.

**5-tuple hash** — хеш-значение, вычисляемое от пяти полей сетевого соединения (протокол транспортного уровня, IP-адрес и порт источника, IP-адрес и порт назначения) и используемое для устойчивой привязки соединения к узлу обработки трафика.

**CDC (Change Data Capture)** — паттерн захвата изменений данных в базе данных с последующей передачей этих изменений в потоковую систему обработки.

**Chaos testing** — методика проверки отказоустойчивости распределённой системы посредством преднамеренного внесения отказов в её компоненты и наблюдения за поведением системы под отказами.

**Consistent Hashing** — семейство алгоритмов, минимизирующих перераспределение ключей между узлами при изменении состава кластера c помощью хеширования.

**Control Plane, CPL** — компонент, который отвечает за уровень управления: хранение конфигураций, размещение целевых групп и координацию узлов плоскости данных.

**Data Plane, DPL** — уровень обработки сетевых пакетов на котором осуществляется непосредственная балансировка трафика.

**DSR (Direct Server Return)** — схема, при которой ответный трафик от сервера обработки трафика направляется клиенту напрямую, минуя балансировщик нагрузки.

**eBPF (extended Berkeley Packet Filter)** — технология безопасного исполнения программ внутри ядра Linux, применяемая для сетевой обработки, наблюдаемости и фильтрации.

**ECMP (Equal-Cost Multi-Path)** — механизм маршрутизации, позволяющий распределять трафик между несколькими равнозначными по стоимости путями.

**Endpoint** — пара IP-адреса клиентского сервера и порта, идентифицирующая конкретный сервер обработки трафика в составе целевой группы балансировщика.

**etcd** — распределённое отказоустойчивое хранилище типа "ключ-значение", обеспечивающее линеаризуемые операции и используемое для координации и хранения конфигурации.

**Gossip/SWIM** — семейство полностью децентрализованных протоколов обнаружения и мониторинга членства узлов в распределённом кластере, основанных на случайном обмене сообщениями между узлами.

**gRPC** — фреймворк удалённого вызова процедур с двоичной сериализацией и поддержкой потоковых вызовов, применяемый для взаимодействия плоскости управления и узлов плоскости данных.

**Health Check, HC** — процесс периодического опроса эндпоинтов с целью определения их работоспособности.

**Kernel bypass** — подход к высокопроизводительной сетевой обработке, при котором пакеты передаются между сетевой картой и пользовательским пространством, минуя сетевой стек ядра.

**L3/L4** — сетевой и транспортный уровни эталонной модели OSI, на которых работают рассматриваемые в работе балансировщики нагрузки, оперирующие IP-адресами и портами без анализа прикладных данных.

**LBaaS (Load Balancer as a Service)** — модель предоставления балансировщика нагрузки как управляемого сервиса в облаке.

**Long-poll** — техника взаимодействия клиента и сервера, при которой сервер удерживает запрос до появления новых данных или истечения заданного таймаута.

**Placement** — отображение множества целевых групп на конкретные узлы плоскости данных.

**Reconciliation** — процесс приведения фактического состояния системы к желаемому, в результате которого исполнитель применяет необходимые изменения и фиксирует достигнутый результат.

**Replication Factor** — число копий целевой группы или vshard, размещаемых на различных узлах для обеспечения отказоустойчивости.

**RIP (Real IP)** — реальный IP-адрес конкретного узла обработки трафика.

**SLA (Service Level Agreement)** — соглашение об уровне обслуживания, определяющее гарантии доступности и производительности сервиса.

**StatefulSet** — тип рабочей нагрузки в Kubernetes, обеспечивающий стабильные сетевые идентификаторы и упорядоченное развёртывание для приложений с состоянием.

**Target Group, TG** — логическая группа эндпоинтов, объединённых общим VIP, портом и протоколом транспортного уровня (TCP или UDP).

**VIP (Virtual IP)** — виртуальный IP-адрес, предоставляемый балансировщиком для приёма пользовательского трафика и позволяющий абстрагировать клиента от конкретных узлов обработки.

**VPP (Vector Packet Processing)** — высокопроизводительный фреймворк обработки сетевых пакетов с применением векторной обработки и kernel bypass.

**Vshard** — промежуточная единица шардирования, используемая при двухуровневом консистентном хешировании для распределения эндпоинтов между узлами кластера проверок состояния.

**XDP (eXpress Data Path)** — программируемый сетевой механизм Linux на основе eBPF, позволяющий обрабатывать пакеты на этапе их поступления в драйвер сетевой карты, до основной части сетевого стека.
